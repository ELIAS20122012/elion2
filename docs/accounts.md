# حساب‌های کاربری داشبورد

کسی که یوزر و رمز نداشته باشد وارد نمی‌شود، و این تصمیم را **سرور** می‌گیرد نه مرورگر. دستکاری
localStorage یا رد شدن از صفحه‌ی خوش‌آمد هیچ فایده‌ای ندارد: هر درخواست بدون نشست معتبر با ۴۰۱ رد
می‌شود.

## دو نقش

| نقش | چه می‌تواند بکند |
|---|---|
| `admin` | همه‌چیز؛ تنها نقشی که می‌تواند کاربر بسازد یا سفارش بفرستد |
| `viewer` | فقط خواندن. هر درخواست نوشتنی رد می‌شود، از جمله `POST /accounts/{id}/order` |

`viewer` برای شاگردهاست. فعلاً **همه‌ی حساب‌ها را می‌بیند**؛ جداسازی داده‌ی هر کاربر هنوز ساخته
نشده (پایین‌تر).

## ساخت اولین حساب

تا وقتی هیچ کاربری ساخته نشده، API باز است — عمداً، تا کسی پشت در خودش نماند. بعد از ساختن اولین
حساب، در بسته می‌شود.

```bash
cd backend
.venv\Scripts\python.exe -m journal.users add elias --admin
```

رمز را همان‌جا تایپ می‌کنید؛ روی صفحه نمایش داده نمی‌شود، در تاریخچه‌ی شل نمی‌ماند، و هیچ‌جای این
مخزن نوشته نمی‌شود. فقط هش bcrypt آن به دیتابیس می‌رود.

> پس از ساختن اولین کاربر باید سرور ژورنال یک بار ری‌استارت شود تا کد جدید فعال شود (پنجره‌ی
> `run-journal.bat` را ببندید و `start-services.ps1` را دوباره اجرا کنید).

## بقیه‌ی دستورها

```bash
.venv\Scripts\python.exe -m journal.users list
.venv\Scripts\python.exe -m journal.users add ali            # viewer
.venv\Scripts\python.exe -m journal.users passwd elias       # عوض کردن رمز
.venv\Scripts\python.exe -m journal.users disable ali        # بستن دسترسی
.venv\Scripts\python.exe -m journal.users enable ali
```

عوض کردن رمز یا غیرفعال کردن یک حساب، **تمام نشست‌های باز آن کاربر را همان لحظه می‌بندد**.

## چطور کار می‌کند

- رمزها با bcrypt هش می‌شوند؛ رمز اصلی هیچ‌وقت ذخیره نمی‌شود.
- نشست یک توکن تصادفی ۳۲ بایتی است که در کوکی `elion_session` با `HttpOnly` می‌نشیند — جاوااسکریپت
  صفحه نمی‌تواند بخواندش، پس یک حمله‌ی XSS هم آن را برنمی‌دارد.
- در دیتابیس فقط **هش** توکن نگه داشته می‌شود؛ یک نسخه‌ی دزدیده‌شده از دیتابیس برای ورود به کار
  نمی‌آید.
- «Remember me» روشن = ۳۰ روز، خاموش = ۱ روز.
- نام کاربری به بزرگ و کوچک بودن حروف حساس نیست.
- ورود با نام کاربری ناموجود دقیقاً همان‌قدر طول می‌کشد که ورود با رمز غلط، تا از بیرون نشود فهمید
  کدام حساب وجود دارد.

## این جای Cloudflare Access را نمی‌گیرد

الان دو لایه دارید و هر کدام کار خودش را می‌کند:

| لایه | چه چیزی را می‌بندد |
|---|---|
| Cloudflare Access | چه کسی اصلاً به سایت برسد |
| ورود داشبورد | چه کسی داده را ببیند و چه کاری بکند |

وقتی بخواهید شاگردها وارد شوند، باید Access را برایشان باز کنید یا سایت را از پشت آن بیرون
بیاورید — و آن‌وقت این لایه تنها چیزی است که باقی می‌ماند. پیش از آن روز، موارد زیر را حل کنید.

## چیزهایی که هنوز ساخته نشده

1. **جداسازی داده بین کاربرها.** هر `viewer` الان همه‌ی حساب‌ها و همه‌ی معاملات را می‌بیند. برای
   شاگردها باید هر حساب به یک کاربر گره بخورد و هر کوئری بر اساس آن فیلتر شود.
2. **محدودیت تلاش ورود.** الان می‌شود بی‌نهایت بار رمز را حدس زد. تا وقتی پشت Access هستید مهم
   نیست؛ قبل از باز کردن سایت، لازم می‌شود.
3. **پنل مدیریت کاربر در خود سایت.** فعلاً فقط با خط فرمان.
4. **فراموشی رمز.** راه بازیابی ندارد؛ ادمین با `passwd` عوضش می‌کند.
