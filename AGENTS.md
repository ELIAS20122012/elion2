# Elias OS — guide for coding agents (Claude Code, Antigravity, Codex, …)

Read this whole file before changing anything. Then read `HANDOFF.md` (where the last agent stopped) and
`ROADMAP.md` (what is done / next). The owner is **Elias**; he talks Persian, wants short answers, few
questions, and finished work (tests green, deployed), never half-done features.

## What it is
A personal agentic OS running 24/7 on Elias's Windows desktop PC (`C:\Elion\elias-os`). Telegram bot
**@Elion_OS_bot** is the main interface; a local dashboard (127.0.0.1:7420, remote via Cloudflare Tunnel
`panel.eliongroup.org` + Cloudflare Access) is the second. A **fixed kernel** + **plugins** + **skills**.
Trading (MT4) is only ONE small plugin — never make the core or prompts trading-centric.

## Stack & rules of the code
- Node ≥ 22.18, **TypeScript run directly by Node (type-stripping)**, ESM. No build step.
  → Only *erasable* TS: no `enum`, no `namespace`, **no constructor parameter properties**
  (`constructor(private x)` breaks). Imports use `.ts` extensions.
- Storage: `node:sqlite` (`data/elias.db`, WAL). SQLite is the source of truth; Markdown/Obsidian only for knowledge.
- No new npm dependencies unless really needed (devDeps: typescript, @types/node only).
- Python helpers (faster-whisper, edge-tts, mark_chart) live in `voice/`, `video/` and run in venvs under `data/`.

## How things work (short)
- Everything is a **task** (queued → running → succeeded/failed, retries, verify spec). Providers execute tasks.
- Telegram posts results of tasks whose `source` is not `internal`/`manual`. Background jobs use `source: "internal"`.
- **Approvals**: capabilities like `publish:*`, `send:*`, `payment:*`, `trade:execute` need Elias's approval (kernel policy).
- Plugins react to finished tasks with `kernel.addEventSink` (chains: plan → media-gen → publish, research → Obsidian …).
- Persona for chat agents is generated by `writePersona` (config.ts) into `data/workspace/CLAUDE.md` + `AGENTS.md`
  — that is NOT this file. Edit the persona there.

## Hard rules (never break)
1. **Never read, print, copy or commit secrets**: `config/secrets.json`, `config/google-token.json`,
   `config/google-client.json`, tunnel token. Backups must never include them.
2. **Paid actions** (Veo/Gemini image, Vertex) need Elias's prior approval; never auto-retry paid generation (maxAttempts 1).
3. **Publishing** (YouTube etc.) always goes through an approval. MT4 bridge is **read-only** — no trading code, ever.
4. No credentials typed into web pages by agents; Elias pastes keys into the `setup/*-key.cmd` scripts himself.
5. Do not rewrite git history (no force push / rebase / amend). Commit small, one feature per commit.
6. **One agent at a time** on this folder. If `HANDOFF.md` says another agent is mid-task, finish/rollback that first.
7. Don't touch `data/` (live DB, venvs, models) except through the code.

## Save tokens: use the code graph first
`graphify-out/GRAPH_REPORT.md` is a map of the whole code base (modules, god nodes, communities), rebuilt nightly.
Before opening files, find the right ones with `data\graphify-venv\Scripts\graphify.exe query "<question>" --budget 800`
(or `explain "<Symbol>"`, `affected "<Symbol>"`), then read only those files/lines. After your change:
`data\graphify-venv\Scripts\graphify.exe update .` (local, free, no LLM). Never read graphify-out/graph.json raw.

## Workflow for every change
1. Read `HANDOFF.md`, pick/confirm the task in `ROADMAP.md`.
2. Make the change following existing patterns (look at a similar plugin first).
3. `npm test` (and `npx tsc --noEmit -p .` if TypeScript is installed) — **must be green**. Add a test for new logic.
4. Restart the running daemon: create the empty file `data\restart.flag` (or Telegram `/restart`).
   After ~20 s check `data\daemon.log` ends with `daemon.started` and no errors.
5. `git add -A && git commit -m "<what>"` (local only).
6. Update `HANDOFF.md` (what you did, what is left, anything risky) and tick `ROADMAP.md`.
